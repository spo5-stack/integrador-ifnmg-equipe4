## Endpoints permitidos

### Perfil — alterar nome

- `PATCH /api/usuarios/nome`

```json
{ "nome": "Novo nome" }
```

- `nome` mínimo 1 (aplicar trim no frontend).
- Resposta `200`: `{ "id": "uuid", "nome": "Novo nome", "email": "..." }`.
- Erros: `400` payload inválido; `404`/`401` conforme contrato; `500`.

### Perfil — alterar senha

- `PATCH /api/usuarios/senha`

```json
{ "senhaAntiga": "segredo123", "senhaNova": "novoSegredo123" }
```

- `senhaNova` mínimo 6 no backend. O frontend deve exigir mínimo 8 e ao menos uma
  letra e um número (ver “Validação local”), sem inventar campos no payload.
- Resposta `200`: `{ "id", "nome", "email" }` (não retorna token).
- Senha antiga inválida deve ser tratada como erro de validação/negócio do
  backend: exiba a mensagem do backend (`{ erro }`) quando existir, senão
  “Senha atual incorreta. Verifique e tente novamente.”.

### Perfil — excluir conta

- `DELETE /api/usuarios` — sem corpo, resposta `204`.
- Após `204`: limpe a sessão e navegue para `/login`.

### Esqueci minha senha — nenhum endpoint

- **Não existe** endpoint de recuperação de senha nem de redefinição por código
  em `docs/api-routes.md`. Não chame `POST /api/auth/forgot-password`,
  `POST /api/auth/reset-password` ou qualquer rota inventada. O `api.ts` não deve
  ganhar rotas novas.
- A tela é **somente UI** (UI-only): simula o envio com `setTimeout`/estado local,
  mostra a confirmação “Código enviado com sucesso!” e limpa o formulário.
- Registre a lacuna em `docs/backend-changes/04-add-password-recovery-endpoints.md`
  (ver “Documentação de lacuna do backend”), sem implementar nada no backend.

### Auxiliares

- Nenhum `GET /api/usuarios` existe. Para exibir o e-mail e preencher o nome
  inicial use `useAuth().usuario` (campos `id`, `nome`, `email`).

## Arquitetura obrigatória

O projeto migrou de `src/features/` para uma estrutura simplificada. Siga o
padrão das telas já migradas:

```text
src/

    usuario.ts                 # DTOs (criar; pode reexportar/tipar Usuario)
  services/
    usuarioService.ts          # chamadas axios tipadas
  hooks/
```

Regras:

  usando TanStack Query (`useMutation`) como nas tasks anteriores.
- `interfaces/<recurso>.ts` contém os DTOs TypeScript puros.
- Validação com React Hook Form + Zod em componentes de formulário, no padrão de
  `src/components/register/RegisterForm.tsx`.
- Use `import type`; não use `any`, enums ou `namespace`.

## Sessão após alterar o nome

O nome do usuário é exibido no app a partir de `useAuth().usuario`. Para que a
mudança apareça imediatamente:

- Depois de `PATCH /api/usuarios/nome` retornar `200`, atualize a sessão salva
  preservando o token atual. O lugar correto é o `AuthContext`: adicione algo
  como `updateUsuario(usuario: Usuario)` que salva
  `{ ...session, usuario }` com `saveSession(session, remember)` — mantenha um
  `remember` no estado do provider (ou torne explícito no `signIn`) para não
  mover a sessão entre `localStorage` e `sessionStorage`.
- Não decodifique o JWT. Não chame `signIn` novamente.
- Após alterar a senha, **não** é necessário novo login: o backend não invalida o
  token e não retorna token novo. Documente essa decisão na entrega.

## Design — Configurações (Perfil)

Composição baseada em `perfil/perfil.html`, dentro de `AuthenticatedLayout`:

- Cabeçalho da página: título **“Configurações”** em `font-heading` e subtítulo
  “Gerencie seus dados pessoais e preferências.” em `text-muted-foreground`.
- Grid de 2 colunas no desktop (`md:grid-cols-2`) e 1 no mobile, `gap-6`:

1. **Card “Alterar Nome”**
   - Label `label-caps` **NOME**; `Input` pré-preenchido com
     `usuario?.nome`, placeholder “Seu nome”; `autoComplete="name"`.
   - Botão **“Salvar Nome”** (`Button` primário). Durante o envio, desabilite e
     mostre estado de loading acessível (`aria-busy`).
   - Em sucesso, mostre `SuccessBanner`: “Nome atualizado com sucesso!” e atualize
     a sessão (`updateUsuario`).

2. **Card “Alterar Senha”**
   - Label **SENHA ATUAL** (`Input type="password"`,
     `autoComplete="current-password"`) e **NOVA SENHA** (`Input type="password"`,
     `autoComplete="new-password"`, com toggle `Eye`/`EyeOff`).
   - Botão **“Salvar Senha”**.
   - Em sucesso: “Senha alterada com sucesso!” via `SuccessBanner` e limpe os
     campos do formulário.
   - Em erro de senha atual: mensagem do backend quando existir.

3. **Card “Zona de Perigo”** (largura total, abaixo do grid)
   - Título em `font-heading`, texto “Excluir sua conta remove todos os dados
     permanentemente.” e botão **“Excluir Conta”** usando `Button` com
     `variant="destructive"` (o token `--destructive` muda no modo escuro, então
     não use `text-white` fixo).
   - A exclusão pede **confirmação acessível** via `AlertDialog` (não use
     `window.confirm`). A referência tem dupla confirmação; um `AlertDialog` com
     texto explícito (“Esta ação é irreversível…”) é suficiente.
   - Em `204`: limpe a sessão (`logout()`), navegue para `/login` e exiba o
     aviso de conta excluída via `location.state` (mesmo padrão de
     `SuccessBanner` usado nas tasks anteriores).
   - Em `401`/`404`/`500`/falha de rede: exiba erro acessível e mantenha a conta.

### Estados obrigatórios

- Loading em cada mutação (botão desabilitado + `aria-busy`).
- Erro acessível (`role="alert"`), com a mensagem do backend quando existir.
- Sucesso via `SuccessBanner`.
- A tela não busca dados no `GET`; se `usuario` for `null`, redirecione para
  `/login` (o `PrivateRoute` já cobre isso, mas não quebre o layout).

### Validação local (Perfil)

- **Nome:** obrigatório após `trim` (mínimo 1). Se o nome não mudou, permita o
  envio (o backend responde `200`) ou desabilite o botão — escolha uma das opções
  e documente; prefira desabilitar com `disabled` e `title` explicativo.
- **Senha:** `senhaAntiga` obrigatória; `senhaNova` obrigatória, mínimo 8, com ao
  menos 1 letra e 1 número; `senhaNova` deve ser diferente de `senhaAntiga`
  (mensagem “A nova senha deve ser diferente da senha atual.”), como na
  referência.
- Não adicione campo “confirmar nova senha” na tela de perfil: o contrato do
  backend só aceita `senhaAntiga` e `senhaNova`, e a referência não tem esse
  campo. Se optar por incluir por segurança de digitação, valide apenas no
  cliente e não envie o campo extra.
- Limpe os erros ao digitar. Não use `alert()`/`confirm()` nativos.
