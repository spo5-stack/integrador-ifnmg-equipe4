## Endpoints permitidos

Use exclusivamente:

### Criar galpão

`POST /api/galpoes`

```json
{ "nome": "Galpão Norte", "capacidade": 1500 }
```

Regras do backend:

- `nome` mínimo 1;
- `capacidade` inteiro maior que 0;
- resposta `201` com `{ id, nome, capacidade, criadoEm, atualizadoEm }`;
- erros `400` e `500`.

### Buscar galpão (detalhe)

`GET /api/galpoes/{id}`

Resposta `200`:

```json
{
  "id": "uuid",
  "nome": "Galpão Norte",
  "capacidade": 1500,
  "criadoEm": "2026-10-22T18:00:00.000Z",
  "atualizadoEm": "2026-10-22T18:00:00.000Z",
  "lotes": [
    {
      "id": "uuid",
      "quantidade": 1200,
      "dataInicio": "2026-10-01T00:00:00.000Z",
      "status": "ATIVO",
      "fase": "CRESCIMENTO",
      "criadoEm": "2026-10-01T00:00:00.000Z",
      "atualizadoEm": "2026-10-01T00:00:00.000Z"
    }
  ],
  "dispositivos": [
    {
      "id": "uuid",
      "nome": "Sensor 1",
      "modelo": "LDR-01",
      "status": "ATIVO",
      "criadoEm": "2026-10-01T00:00:00.000Z",
      "atualizadoEm": "2026-10-01T00:00:00.000Z",
      "ultimaLeitura": {
        "valor": 42,
        "criadoEm": "2026-10-22T18:00:00.000Z"
      }
    }
  ]
}
```

Observações:

- `lotes` vem ordenado por `dataInicio` desc.
- `dispositivos` vem ordenado por `criadoEm` asc.
- `ultimaLeitura` pode ser `null`.
- O endpoint retorna `404` para galpão inexistente e `400` para UUID inválido.
- Não chame `GET /api/galpoes/{id}/status` nesta task; o detalhe já traz os
  dados necessários.

### Atualizar galpão

`PUT /api/galpoes/{id}`

```json
{ "nome": "Galpão Norte", "capacidade": 1800 }
```

- Campos são opcionais, mas envie nome e capacidade preenchidos.
- Resposta `200` com os dados básicos atualizados.
- Erros: `400`, `404`, `409` e `500`.
- `409` ocorre, por exemplo, ao alterar a capacidade de um galpão que possui
  lote ativo. Exiba a mensagem do backend.

### Regra de 401

O `api.ts` já trata `401` globalmente. Não duplique essa lógica.

## Arquitetura MVC obrigatória

Preserve as camadas existentes e estenda a feature `galpoes`:

```text
src/features/galpoes/

  controller/
```

Regras:

- `view` não importa `axios` nem serviços HTTP.
- `model` contém DTOs e funções HTTP tipadas.
- `controller` controla carregamento, validação, erros, submit e navegação.
- Use `import type`; não use `any` nem enums.
- Não use `useEffect` para sincronizar formulário com dados já carregados de
  forma síncrona. Preencha o formulário no `.then()` da requisição.
- Componentes de formulário devem ser acessíveis e reutilizáveis.
- Não crie um controller genérico complexo; prefira controllers pequenos.

## Model e serviços

Estenda `galpao.types.ts` com tipos como:

```ts
export type StatusRegistro = "ATIVO" | "DESATIVADO"

export type LoteDoGalpao = {
  id: string
  quantidade: number
  dataInicio: string
  status: string
  fase: string
  criadoEm: string
  atualizadoEm: string
}

export type DispositivoDoGalpao = {
  id: string
  nome: string
  modelo: string
  status: StatusRegistro
  criadoEm: string
  atualizadoEm: string
  ultimaLeitura: { valor: number; criadoEm: string } | null
}

export type GalpaoDetalhe = Galpao & {
  lotes: LoteDoGalpao[]
  dispositivos: DispositivoDoGalpao[]
}

export type CriarGalpaoDados = {
  nome: string
  capacidade: number
}

export type AtualizarGalpaoDados = Partial<CriarGalpaoDados>
```

Estenda `galpao.service.ts` com:

- `obterGalpao(id: string): Promise<GalpaoDetalhe>`;
- `criarGalpao(dados: CriarGalpaoDados): Promise<Galpao>`;
- `atualizarGalpao(id: string, dados: AtualizarGalpaoDados): Promise<Galpao>`.

Use `encodeURIComponent(id)` nas URLs. Não hardcode a base URL.

## Formulário compartilhado

Crie `GalpaoForm.tsx` como componente de apresentação reutilizado por Criar e
Editar.

Sugestão de props:

```ts
type GalpaoFormProps = {
  nome: string
  capacidade: string
  errors: { nome?: string; capacidade?: string; geral?: string }
  isSubmitting: boolean
  submitLabel: string
  onChangeNome: (valor: string) => void
  onChangeCapacidade: (valor: string) => void
  onSubmit: (event: FormEvent<HTMLFormElement>) => void
  cancelHref: string
}
```

Regras do formulário:

- Título do card/form com Manrope.
- Campos:
  - **Nome do Galpão** — `Input`, obrigatório, placeholder
    “Ex: Galpão Norte 01”.
  - **Capacidade (aves)** — `Input type="number"`, `min="1"`, `step="1"`,
    `inputMode="numeric"`, placeholder “Ex: 500”.
- Labels associados com `htmlFor`.
- Erros por campo em `text-destructive`, com `aria-invalid` e
  `aria-describedby`.
- Erro geral em banner com `role="alert"`.
- Botão “Cancelar” como link de volta para a rota informada.
- Botão de submit:
  - label “Salvar”;
  - `isSubmitting` desabilita o botão e exibe `Loader2` com “Salvando...”;
  - `aria-busy`.
- Não envie requisição se a validação local falhar.
- `prefers-reduced-motion`: use `motion-reduce:animate-none` em spinners.

## Validação local

Antes de chamar a API:

- `nome`: `trim()`, não pode ser vazio.
- `capacidade`: converter para número, exigir inteiro e maior que zero.
- Rejeitar `NaN`, `Infinity`, decimais e valores negativos.
- Enviar `nome` já com trim e `capacidade` como number.
- Não limitar o tamanho do nome no frontend além do necessário; o backend não
  documenta limite.

Mensagens sugeridas:

- “Informe o nome do galpão.”
- “Informe uma capacidade inteira maior que zero.”

Composição baseada em `galpao-editar.html`:

- Obter `id` com `useParams`.
- Buscar dados com `GET /api/galpoes/{id}`.
- Enquanto carrega, exibir skeleton do formulário.
- Em `404` ou `400`, exibir estado “Galpão não encontrado” com link para
  `/galpoes`.
- Em erro de rede, exibir `RequestError` com retry.
- Após carregar, preencher nome e capacidade.
- Link “Voltar” para `/galpoes`.
- Título “Editar Galpão”.
- Subtítulo “Altere os dados do galpão.”
- Mesmo card e formulário da tela de criação.
- Em sucesso:
  - navegar para `/galpoes`;
  - passar `state={{ sucesso: "Galpão atualizado com sucesso." }}`.
- Em `409`, exibir a mensagem do backend (ex.: capacidade incompatível com lote
  ativo) e manter os dados no formulário.
- Em `404`, informar que o galpão não existe mais e oferecer voltar à listagem.

## Tela — Detalhe do Galpão

Composição baseada em `galpao-detalhe.html`, adaptada ao que o backend expõe:

- Link “Voltar” para `/galpoes`.
- Cabeçalho:
  - nome do galpão em `font-heading`;
  - “Capacidade: X aves” em `text-muted-foreground`;
  - botão “Editar” com ícone `Pencil` linkando para
    `/galpoes/{id}/editar`.
- Dois cards de resumo:
  - **Lote Ativo**:
    - se houver lote com `status === "ATIVO"`, exibir badge da `fase`,
      quantidade de aves e dias desde `dataInicio`;
    - se não houver, exibir “Nenhum lote ativo”;
    - não invente a fase; renderize a string recebida.
  - **Dispositivos**:
    - total de dispositivos;
    - texto “cadastrados”.
- Card/tabela **Lotes**:
  - colunas: Quantidade, Data Início, Status, Fase e Ações;
  - status e fase como badges;
  - `dataInicio` formatada com `toLocaleDateString("pt-BR")`;
  - ação “Encerrar” desabilitada com título “Disponível em breve” apenas para
    lote ativo;
  - cabeçalho com ação “Cadastrar Lote” desabilitada com o mesmo aviso;
  - estado vazio “Nenhum lote neste galpão.”
- Card/tabela **Dispositivos**:
  - colunas: Nome, Modelo, Status e Última Leitura;
  - **não exiba coluna “Credencial”**: o backend não retorna credencial;
  - status como badge;
  - última leitura: `valor%` e data/hora em `pt-BR`; se `null`, exibir “—”;
  - cabeçalho com ação “Adicionar” desabilitada com aviso “Disponível em breve”;
  - estado vazio “Nenhum dispositivo neste galpão.”
- Estados obrigatórios: loading com skeleton, erro com retry e não encontrado.
- Não implemente ações de lote/dispositivo além dos links desabilitados.
- Não implemente exclusão nesta tela.

## Badges e formatação

- Status `ATIVO`: `bg-secondary text-secondary-foreground`.
- Status `DESATIVADO`: `bg-muted text-muted-foreground`.
- Fase conhecida:
  - `INICIAL`: `bg-accent text-accent-foreground`;
  - `CRESCIMENTO`: `bg-secondary text-secondary-foreground`;
  - `PRODUCAO`: `bg-primary text-primary-foreground`.
- Para fase desconhecida, use `bg-muted text-muted-foreground`; não invente
  novas cores.
- Badges: `rounded-full px-3 py-1 text-xs font-semibold`.
- Não dependa apenas de cor; o texto do badge já comunica o estado.
- Use `Intl`/`toLocaleString("pt-BR")` para datas. Não adicione biblioteca de
  datas.

- Reutilize os tokens semânticos; não use hex no JSX.
- Títulos em `font-heading`; corpo/tabelas em `font-sans`.
- Formulário: card `bg-card`, `border-border`, `rounded-xl`, `p-6 md:p-8`,
  `max-w-2xl`, sombra suave.
- Inputs: `bg-muted`, borda `border-input`, `rounded-lg`, `py-3`, foco com
